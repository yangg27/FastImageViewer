# FastImageViewer · 极速看图

> 一个只做三件事的 Windows 图片查看器：**打开图片、复制到剪贴板、保存到本地**。
> 没有相册管理、没有编辑、没有云同步、没有后台常驻 —— 换来的是极致的启动速度和极小的内存占用。

## 为什么还要再造一个看图软件？

Windows 自带的「照片」应用启动要 3~5 秒，还常驻后台、自动扫描图库、联网推荐。
而实际使用时，90% 的场景只是**想快点看一眼这张图**。

FastImageViewer 只保留最高频的三个动作，其余全部砍掉：

| | Windows 照片 | 本项目 |
|---|---|---|
| 启动到出图 | 3~5 秒 | **0.6 秒** |
| 常驻内存 | 100~300 MB | **36 MB** |
| 后台进程 | 多个 | **0 个** |
| 打开 1 亿像素大图 | 卡顿明显 | **0.5 秒** |

## 功能

程序**只有**三个核心功能，加若干查看便利操作：

| 功能 | 操作 | 快捷键 |
|---|---|---|
| 打开图片 | 双击图片自动唤起 / 拖入窗口 / 工具栏「打开」 | `Ctrl+O` |
| 复制到剪贴板 | 工具栏「复制到剪贴板」 | `Ctrl+C` |
| 保存到本地 | 工具栏「保存到本地」→ 存到固定目录 | `Ctrl+S` |
| 另存为（附加） | 指定路径保存一份 | `Ctrl+Shift+S` |

### 看图操作（v1.1.0 增强）

| 操作 | 快捷键 |
|---|---|
| **上一张 / 下一张** | `←` `→`（或 `↑` `↓`、`A` `D`、`PageUp` `PageDown`、`空格`） |
| 首张 / 末张 | `Home` / `End` |
| 缩放 / 复位 | 滚轮 或 `+` `-` / `0` |
| 关闭 | `Esc` |

- **左右箭头换图**：打开任意一张图片后，程序自动把**同目录**的图片列成一个浏览列表，
  按 `←` `→` 即可连续翻看，到头自动回绕（第一张再往左=最后一张）。
- **打开单张图也有得翻**：双击打开单个文件时，会自动扫描该文件所在目录的全部图片，
  而不是只锁定你点的那一张 —— 这是换图功能的前提。
- **自然序排列**：`img2.png` 排在 `img10.png` 之前（按数字大小，不是字典序）。
- **相邻图预取**：读到当前图时会顺手把相邻两张解码好放进内存，按箭头几乎零等待；
  预取有硬上限（单文件 ≤12 MB、≤5000 万像素），超限自动跳过，绝不为预取而吃内存。
- **自动跳过坏图**：目录里夹着损坏文件或不支持的格式时，按箭头会自动跳过，不会中断浏览。
- **状态栏序位**：右上角显示 `[当前/总数]`，随时知道看到第几张。

- **保存目录**：默认 `%USERPROFILE%\Pictures\ImageViewer`，重名自动加 `_1` `_2` 后缀，**不覆盖**
- **支持格式**：`.jpg .jpeg .png .gif .bmp .webp .tiff .tif .ico`（GIF/WebP 动图自动播放）

## 实测数据

Windows 11 x64 环境实测：

### 启动与占用

| 指标 | 数值 |
|---|---|
| 启动到出图（4000×3000 大图） | **均值 610 ms**，最快 553 ms |
| 常驻内存 | **36 MB** |
| 主程序体积 | 2.5 MB（完整目录 38 MB） |
| 后台进程 | 0（无常驻、无服务、无托盘） |

### 各类图片打开耗时

| 图片 | 尺寸 | 文件大小 | 打开耗时 |
|---|---|---|---|
| 普通照片 | 4000×3000 | ~1 MB | 0.6 s |
| 4K 图片 | 3840×2160 | ~1 MB | 0.3 s |
| 1 亿像素 JPEG | 10000×10000 | 2 MB | **0.5 s** |
| 2.25 亿像素 PNG | 15000×15000 | 0.7 MB | **13.9 s** |
| 6400 万像素 BMP | 8000×8000 | 183 MB | **0.7 s** |
| 未压缩 TIFF | 8000×8000 | 183 MB | **0.7 s** |

> 2.25 亿像素 PNG 的 13.9 秒是 PNG 无损解码的物理下限（需逐像素还原 2.25 亿个像素）。
> 优化前该用例需要 104.5 秒。

## 安装

### 方式一：使用打包版

1. 从 [Releases](../../releases) 下载 `FastImageViewer-win64.zip` 并解压
2. 运行安装脚本（需本机已安装 Python 3.9+）：
   ```bash
   python install.py
   ```
3. 脚本会自动：复制程序到 `%LOCALAPPDATA%\Programs\FastImageViewer`、注册文件关联、**备份你原有的默认关联**

### 方式二：从源码构建

```bash
# 需要带 tkinter 的 Python（官方安装包默认包含）
pip install pillow pyinstaller

python build.py     # 打包（约 40 秒）
python install.py   # 安装并注册
```

### 设为默认打开方式（重要）

Windows 10/11 从 2024 年起引入了 **UCPD 内核驱动**，禁止任何程序静默修改「默认应用」——
这是微软的反劫持安全机制，所有第三方软件（含付费看图工具）均受此限制。

因此安装后分两种情况：

| 格式 | 说明 |
|---|---|
| `.webp` `.tiff` `.tif` `.ico` | 安装脚本通常可直接设为默认 |
| `.jpg` `.png` `.gif` `.bmp` | 需手动确认一次（约 20 秒，永久生效） |

**手动设置步骤：**

1. 运行 `set_default.py`，按提示回车，会自动打开「默认应用」设置页
2. 搜索框输入 **极速看图**
3. 点击搜到的条目 → 点顶部 **「设置默认值」**
4. 完成，所有图片格式一次性全部生效

> 替代方式：右键任意图片 → **打开方式** → **选择其他应用** → 选「极速看图」→ 勾选**始终** → 确定

## 配置

编辑 `%APPDATA%\FastImageViewer\config.json`（不存在则新建）：

```json
{
  "save_dir": "D:\\我的图片",
  "bg": "#1e1e1e"
}
```

| 字段 | 说明 | 默认值 |
|---|---|---|
| `save_dir` | 「保存到本地」的目标目录 | `%USERPROFILE%\Pictures\ImageViewer` |
| `bg` | 画布背景色 | `#2b2b2b` |

## 技术要点

### 为什么不用 PyInstaller `--onefile`

单文件模式每次启动都要把内部文件（约 17 MB）解压到临时目录，实测启动 **5.6 秒**；
`--onedir` 目录模式只需 **0.6~1.2 秒**，**快约 7 倍**。

本项目核心诉求是「启动快」，因此坚持使用 onedir。这是最重要的一个技术决策。

### 大图快速解码

不同格式走不同的最快路径，而不是「全都全量解码再缩放」：

| 格式 | 策略 | 效果 |
|---|---|---|
| JPEG | `Image.draft()` —— 解码层直接按 N 分之一出图（DCT 缩略解码） | 1 亿像素仅 0.1 s |
| 其他格式 | `Image.reduce(f)` —— 盒式滤波按整数倍率降采样 | 比全解码+LANCZOS 快 4~5 倍 |
| 缩放算法 | 小图用 `LANCZOS`（画质好）；大图换 `BILINEAR` | 避免 LANCZOS 在超大图上的性能崩溃 |

> PNG 10000×10000：优化前 2.92 s → 优化后 **0.63 s**
> PNG 15000×15000：优化前 104.5 s → 优化后 **13.9 s**

### 高保真输出

显示时为了速度会降采样，但**复制到剪贴板和另存为一律重新读取全分辨率原图**，
绝不输出缩略图。原文件同格式保存时直接文件级复制，零画质损失。

### 剪贴板

直接调用 Win32 API 写入 `CF_DIB` + `CF_DIBV5`（零第三方依赖）：

- `CF_DIB`：兼容所有软件（Photoshop / Office / 微信 / QQ / 画图）
- `CF_DIBV5`：额外携带 alpha 通道，透明图片不丢透明度
- 不透明图只写 `CF_DIB`；透明图两个都写，由接收方择优

### 健壮性

针对「大图小图、大文件小文件都不能出 bug」做了专项设计：

- 关闭 Pillow 解压炸弹限制（`MAX_IMAGE_PIXELS = None`），2.25 亿像素不报错
- 开启 `LOAD_TRUNCATED_IMAGES`，半损坏文件尽量出图而非直接失败
- 动图**懒解码**：内存中只保留当前帧，120 帧动图不会一次性吃掉几百 MB
- 帧数上限保护（5000 帧），异常文件不进入死循环
- EXIF 方向自动校正（`exif_transpose`），手机竖拍照片不会横躺
- 所有渲染/保存/复制均有 `MemoryError` 与通用异常兜底，失败只提示不崩溃
- 窗口销毁后不再排程定时任务，避免切换图片时报 `TclError`
- 保存时模式不兼容自动降级（RGBA→白底 RGB），不因格式问题抛异常
- 崩溃日志写入 `%APPDATA%\FastImageViewer\error.log`

```bash
python _tests/_nav_test.py        # 左右键换图专项（31 项）

python _tests/_mem_test.py        # 超大图内存与耗时实测
python _tests/_decode_bench.py    # 解码策略对比基准
python _tests/_smoke_test.py      # 功能冒烟
```

### 翻页性能实测（v1.1.0）

场景：普通 Windows 电脑，翻看手机（1200 万像素）与单反（2400 万像素）照片。

| 指标 | 实测 |
|---|---|
| 翻页均值 | **38 ms** |
| 翻页 P90 | 55 ms |
| 翻页最慢 | 56 ms |
| 反向翻页均值 | 40 ms |
| 内存（含 2 张预取） | 91 MB |

### 覆盖范围

| 维度 | 用例 |
|---|---|
| 极端尺寸 | 1×1、1×5000、5000×1、2×2、7680×4320、10000×10000、15000×15000 |
| 极端文件 | 空文件、300 字节、183 MB |
| 图像模式 | RGB / RGBA / L / LA / P / 1bit / I;16 / CMYK |
| 格式 | JPEG（含渐进式）/ PNG / GIF / BMP / WebP / TIFF（LZW+未压缩）/ ICO |
| 损坏文件 | 空文件、纯文本改名、截断 PNG/JPEG、随机二进制 |
| 文件名 | 中文、空格、`& # @ !` 特殊字符、180 字符超长名 |
| 换图 | 单文件扩展、自然序、回绕、Home/End、坏图跳过、多文件/目录传参 |
| 压力 | 连续切换、120 帧动图、0.02x~40x 极限缩放 |
