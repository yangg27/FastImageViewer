## 二、v1.2.0 迭代内容（本次交付重点）

用户需求："增加一个功能 旋转图片"。

### 设计取舍

旋转功能最大的坑不是"怎么转"，而是**转完之后复制/保存出来的到底是不是转过的图**。
多数看图软件在这里含糊其辞，用户复制出去发现还是歪的。本版明确三条原则：

1. **旋转是视图状态，不改原文件** —— 内存里的 `rotate` 角度，磁盘上的图永远不动。
2. **输出必须跟随** —— 旋转后复制/保存，拿到的就是转正后的图。
3. **换图即复位** —— 旋转只对当前这张生效，不污染下一张。

### 改动清单

| 类别 | 改动 |
|---|---|
| 新增 | `self.rotate` 状态（0/90/180/270），工具栏 `↺` `↻` 两个按钮 |
| 新增 | 快捷键：`R` 右转、`Shift+R` / `L` 左转、`Ctrl+R` 复位 |
| 新增 | `_apply_rotate()`：90° 用 `Image.ROTATE_270`、270° 用 `Image.ROTATE_90`（PIL 常量是**逆时针**，方向易错点） |
| 新增 | 旋转接入 `render()`（在**缩放前**执行，避免先缩后转损失细节） |
| 新增 | `_fit_scale()` 在 90°/270° 时互换宽高，转竖图后自动重新适配窗口 |
| 新增 | `_full_image()` 全路径套旋转，保证复制/保存/剪贴板都是转正结果 |
| 关键修复 | `save_fixed()` / `save_as()` 在 `rotate != 0` 时**放弃 `shutil.copy2` 直复制**，改走 `_save_image()` 重编码 —— 否则"保存"出来的还是原方向 |
| 新增 | 状态栏显示 `· 旋转 90°` |
| 新增 | `open()` 换图时 `self.rotate = 0` 复位 |

### 旋转专项测试（27 项，全通过）

旋转最容易错的两点是**方向**和**输出是否跟随**，因此做了像素级验证而非只看"能不能转"：

| 验证项 | 方法 | 结果 |
|---|---|---|
| 方向正确 | 四角着色测试图，右转后比对每个角的新位置 | 原左下 → 新左上 ✅ |
| 无损性 | 统计旋转前后图像颜色集合 | 完全一致，无插值新色 ✅ |
| 复制跟随 | 旋转后写剪贴板，读回位图尺寸 | 200×120 → **120×200** ✅ |
| 保存跟随 | 旋转后存到固定目录，读回尺寸 | 200×120 → **120×200** ✅ |
| 换图复位 | 旋转后按 `→` 换图，检查 `rotate` | 归 0 ✅ |
| 透明图 | 旋转后取样 alpha | 255 保留 ✅ |
| 边界 | 1×1、动图、180°/270° 累计 | 全部通过 ✅ |

## 三、v1.1.0 迭代内容

用户反馈："读图的时候可以按左右箭头换图"。

### 核心问题定位

v1.0.0 虽然绑定了 `←` `→` 键，但 `step()` 在列表长度 <2 时直接返回；
而**双击打开单张图时列表只有那一条**（`paths=[该文件]`），因此箭头键实际形同虚设。

### 改动清单

| 类别 | 改动 |
|---|---|
| 新增 | 同目录图片扫描（`scan_siblings` / `scan_folder` / `_build_list`） |
| 新增 | 自然序排序：`img2` 排在 `img10` 之前（按数字段切分比较） |
| 新增 | 相邻图**后台线程预取**（线程安全队列回传，不阻塞 UI） |
| 新增 | 状态栏序位显示 `[当前/总数]` |
| 新增 | `Home` / `End` 跳首尾；`↑` `↓` / `A` `D` / `空格` 换图 |
| 新增 | 拖入文件夹 / 批量拖入多个文件 |
| 修复 | 翻页遇坏图时静默跳过，不再弹模态框打断浏览（`open(quiet=True)`） |
| 修复 | **缩放卡死**：8K 图 40 倍 = 530 亿像素导致 `resize` 吃光内存。改为按图尺寸动态算安全倍率上限 + 输出像素护栏（1.2 亿像素） |
| 修复 | `_max_zoom()` 常量漏写 `self.` 前缀导致 `NameError` |
| 修复 | 后台线程调用 `root.after()`（Tk 非线程安全）导致挂起，改用 `queue.Queue` + UI 轮询 |
| 修复 | 窗口关闭后后台任务仍执行导致 `TclError` |

## 六、技术要点

1. **原生 GUI，无浏览器内核** — Python 3.13 + tkinter + Pillow，杜绝 WebView 类方案的启动开销。
2. **`--onedir` 而非 `--onefile`** — 关键性能决策。onefile 每次启动需解压 17 MB 到临时目录（5.6 s），onedir 直接加载（0.6-1.2 s），**快 7.5 倍**。
3. **Win32 剪贴板直写** — 手工构造 `BITMAPV5HEADER`（124 字节），直接写入 `CF_DIB`(8) + `CF_DIBV5`(17)，零依赖且保留 alpha 透明通道。
4. **分级快速解码管线**
   - JPEG 走 `Image.draft("RGB", size)` DCT 域缩略解码，仅解需要的数据。
   - 非动图先 `Image.reduce(factor)` 盒式滤波降采样，再解码。
   - 重采样算法按图大小切换：≤400 万像素用 `LANCZOS`（高质量），>400 万像素用 `BILINEAR`（LANCZOS 在超大图上性能崩溃）。
5. **Pillow 加载懒执行** — PIL 模块延迟到首次真正看图时才 import，压缩冷启动时间。
6. **动图懒解码** — GIF/WebP 动图内存只保留当前帧，避免多帧全解码吃内存。
7. **健壮性加固** — `Image.MAX_IMAGE_PIXELS = None` 关闭解压炸弹限制；`ImageFile.LOAD_TRUNCATED_IMAGES = True` 容错半损坏文件；`ImageOps.exif_transpose()` 校正 EXIF 方向。
8. **无损旋转（v1.2.0）** — 90° 整数倍旋转不用插值（BICUBIC/LANCZOS），走 `transpose` 纯像素坐标搬移，颜色值一个不改、不产生边缘糊化。代价是必须在**缩放之前**旋转。注意 PIL 的 `ROTATE_90` 是**逆时针**，顺时针 90° 须用 `ROTATE_270`。
9. **可见区域渲染（v1.2.0 顺带优化）** — 放大时不再对整个原图 `resize`，而是先裁出可见窗口区域再缩放。8K 图放大 60 倍从 **207 s → 2.74 s**（快 75 倍）。

## 十、待用户手动完成的事项

**设置默认图片程序**（用户已明确自行处理）：

Windows 11 内置 UCPD 内核驱动会拦截程序静默修改默认应用（微软反劫持机制，无法程序化绕过）。请按以下步骤手动设置：

1. 右键任意图片 → **打开方式** → **选择其他应用**
2. 选择 **FastImageViewer**（或"极速看图"）
3. 勾选 **始终使用此应用打开 .xxx 文件**
4. 对 `.jpg / .jpeg / .png / .gif / .bmp / .webp / .tiff / .tif / .ico` 逐个重复

或走：**设置 → 应用 → 默认应用 → 按文件类型选择默认应用**，搜索 `FastImageViewer` 后逐行指定。
